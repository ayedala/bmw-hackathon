# Documentation map

Start with [repository review](REPOSITORY_REVIEW.md) for the challenge assessment, removal suggestions and prioritized additions, or [architecture](ARCHITECTURE.md) for module boundaries. [File inventory](FILE_INVENTORY.md) maps each tracked source and configuration file to its purpose.

[Requirement intelligence](REQUIREMENT_INTELLIGENCE.md) covers the Germany 2030 reasoning chain end to end: which files are canonical and which are fixtures, the CRPS factors, why unknown factors stay as intervals, requirement quality versus decision readiness, where a PM decision is actually recorded, and the known gaps.

[Demo](DEMO.md) describes the presentation, [decision engine](DECISION_ENGINE.md) explains scoring, [data audit](DATA_AUDIT.md) and [contracts](DATA_CONTRACTS.md) cover provenance, and [human review](HUMAN_REVIEW_AND_AUDIT.md) describes audit and PM gates. [Evaluation](EVALUATION.md), [model transfer](MODEL_TRANSFER.md) and [web research](WEB_RESEARCH.md) include proposed work as well as implementation context. [Hosting](HOSTING.md) covers deployment. [Strategy report](REPORT.md) retains the original concept and evidence limits.

The implemented structure is authoritative in the architecture page. Evaluation targets and proposed future workflows are not measured results or completed features.
